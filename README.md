# نظام إدارة Almohamady

واجهة React وVite لإدارة الطلاب والمعلمين وأولياء الأمور والحصص والمدفوعات، مع Supabase Auth وRow Level Security.

## التشغيل

يتطلب المشروع Node.js **22.12 أو أحدث**.

```bash
npm install
npm run dev
```

## النشر

1. أنشئ إعدادات البناء في منصة الاستضافة كمتغيري بيئة:
   - `VITE_SUPABASE_URL`: رابط مشروع Supabase.
   - `VITE_SUPABASE_ANON_KEY`: مفتاح `anon` أو `publishable` العام فقط.
2. نفّذ `npm run build`، وارفع محتويات مجلد `dist` الناتج إلى استضافة مواقع ثابتة تدعم HTTPS.
3. أضف رابط الموقع المنشور إلى **Supabase → Authentication → URL Configuration → Site URL** و**Redirect URLs**، مع إبقاء `http://localhost:5173` ضمن Redirect URLs للتطوير المحلي.
4. اختبر تسجيل الدخول والتسجيل واستعادة كلمة المرور، ثم جرّب عمليات القراءة والإضافة والتعديل والحذف والإيصالات بحسابات تجريبية لكل دور.

لا ترفع `.env` إلى المستودع. ملف `.env.example` يحتوي أسماء الإعدادات وقيمًا توضيحية فقط. مفتاح `anon`/`publishable` مخصص للاستخدام في المتصفح مع سياسات RLS صحيحة؛ **مفتاح `service_role` أو أي سر إداري لا يوضع في متغير يبدأ بـ `VITE_` ولا يُرفع للاستضافة الأمامية**.

## إعداد Supabase

1. انسخ Project URL ومفتاح `anon` أو `publishable` إلى `.env`:

   ```env
   VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
   VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
   ```

2. في Supabase SQL Editor شغّل ملفات الترحيل الأربعة الأولى بالترتيب:
   - `supabase/migrations/20261008_normalize_teacher_name.sql`
   - `supabase/migrations/20261008_admin_email_access.sql`
   - `supabase/migrations/20261008_role_based_access.sql`
   - `supabase/migrations/20261009_financial_tracking.sql`

3. فعّل تأكيد البريد الإلكتروني في **Authentication → Settings** قبل فتح التسجيل العام.
4. أنشئ حساب المدير `infoalmohamadyacadmy@gmail.com` من **Authentication → Users**، وأكد عنوان بريده.
5. بعد إنشاء حساب المدير وتأكيده، شغّل وحده `supabase/migrations/20261010_admin_allowlist.sql`. هذا الترحيل يضيف معرّف حساب المدير الموجود إلى قائمة سماح خاصة؛ إنشاء حساب آخر بالبريد نفسه لا يمنحه صلاحية الإدارة. إذا كنت قد شغّلت الترحيلات الأربعة السابقة بالفعل، فلا حاجة لإعادتها؛ نفّذ هذا الترحيل الأخير فقط.
6. شغّل `supabase/migrations/20261011_admin_management.sql` بعد ترحيل قائمة السماح. ينشئ هذا الترحيل جدول المديرين إذا لم يكن موجودًا ويضيف المدير الأساسي المؤكد عند الحاجة. يستطيع المدير بعدها إضافة حسابات مديرين مؤكدة من قسم **إدارة المديرين** في لوحة التحكم. يجب إنشاء الحساب وتأكيد بريده أولًا من **Authentication → Users**؛ لا يظهر دور المدير في التسجيل، ولا يطلب نموذج الدخول اختيار الدور، إذ يحدد النظام صلاحية المستخدم بعد التحقق من قاعدة البيانات.
7. إذا لم يعمل تسجيل الدخول، استخدم **نسيت كلمة المرور؟** بعد إدخال البريد؛ رابط الاستعادة يعيدك إلى عنوان الموقع الحالي. عند النشر، أضف عنوان الموقع إلى **Authentication → URL Configuration → Redirect URLs**.
8. يستطيع الطالب والمعلم وولي الأمر إنشاء حساب من شاشة التسجيل. تُحفظ بيانات ملفهم تلقائيًا في جدول الدور المناسب ويرتبط سجلهم بحساب Auth. الطالب وولي الأمر يحصلان على صلاحية قراءة سجلهما، بينما يظل حساب المعلم معلقًا حتى يوافق المدير من قسم **طلبات التسجيل**.
9. يربط المدير ولي الأمر بالطالب من حقل **ولي الأمر** في نموذج الطالب. لا يستطيع ولي الأمر ادعاء ربطه بطالب بنفسه؛ وتظهر له الحصص والمدفوعات فقط بعد هذا الربط.
10. بعد تسجيل الطالب، يختار المدير المعلم والمقرر من قسم الطلاب. عند اختيار الطالب في نموذج الحصة، تُملأ المعلمة/المعلم والمقرر وسعر المقرر تلقائيًا إذا كانت محددة؛ كما يُقترح سعر المقرر في نموذج دفعة الطالب، وأجر الحصة إذا كان راتب المعلم محسوبًا لكل حصة. يستطيع المدير مراجعة هذه القيم وتعديلها قبل الحفظ.
11. يمكن للمدير البحث في السجلات وتعديلها وحذفها. حذف السجل نهائي وقد يمنعه وجود سجلات مرتبطة به. الحصة تدعم الحالات: مجدولة، مكتملة، غائب، وملغاة. سجل الدفع يتضمن طريقة الدفع، مرجع التحويل، حالة المراجعة، رقم الإيصال والفترة التي يغطيها؛ ويمكن إرفاق صورة JPG/PNG أو ملف PDF حتى 5 ميجابايت. تحفظ الإيصالات في مخزن خاص ولا يستطيع عرضها إلا المدير وصاحب السجل المرتبط (والد الطالب/المعلم عند انطباق الصلاحية). استخدم حالة **قيد المراجعة** للتحويل غير المؤكد، ثم عدّل السجل إلى **مؤكد** بعد التحقق منه.
12. تعرض لوحة المدير المتأخرات التقديرية على أساس أسعار الحصص **المكتملة** والمدفوعات المؤكدة؛ ومستحق المعلمين مبني على أجر الحصص المكتملة المسجل، ولا يشمل الرواتب الشهرية الثابتة. هذه المؤشرات لا تغني عن مراجعة الحسابات والفترات المسجلة.

تسجيل الدخول يتحقق من كلمة المرور والدور عبر Supabase Auth و`user_roles`. سياسات Row Level Security تمنع المستخدمين من قراءة إلا البيانات المرتبطة بهم، بينما إدارة السجلات ومراجعة المعلمين محجوزتان للمدير. يجب إعادة تشغيل ملفات الترحيل بعد كل تحديث للمخطط، ولا تُعتبر التغييرات متاحة على قاعدة البيانات قبل تطبيقها في SQL Editor.

لا تضع مفتاح `service_role` في تطبيق المتصفح أو ملف `.env` المستخدم بواسطة Vite.
